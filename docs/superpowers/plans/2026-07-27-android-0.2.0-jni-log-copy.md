# Android 0.2.0 JNI and Log Copy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the broken Android 0.2.0 release with a correctly bound
tun2socks JNI bridge and a reliable copy-log action.

**Architecture:** Keep the pinned hev JNI implementation and make the Kotlin
bridge mirror its four descriptors exactly. Add a small native Android
clipboard command behind the existing Rust/Tauri bridge, while a pure
TypeScript helper owns copy-result behavior for the shared log modal.

**Tech Stack:** Kotlin/JNI, Android Gradle Plugin, Rust/Tauri 2, Svelte 5,
TypeScript/Vitest, GitHub CLI.

## Global Constraints

- Keep `versionName = 0.2.0` and `versionCode = 2000`.
- Build an arm64 APK with the existing 0.2 signing certificate.
- Do not run live VPN, reconnect, public-IP, DNS, or leak tests on the host.
- Do not modify or republish the Linux repository or Linux 0.2.0 release.
- Do not delete the existing Android release or tag until replacement artifacts
  pass all tests and signature checks.
- Do not add AI attribution or co-author markers to commits.

**Interfaces:**

- Produces: Tauri command `write_clipboard(text: String)` and Android plugin
  command `writeClipboard({ text })`.

- [ ] **Step 1: Write failing TypeScript behavior tests**

```ts
it("copies the exact displayed text", async () => {
  let written = "";
  const result = await copyDisplayedLog("[1] first\n[2] second\n", async (text) => {
    written = text;
  });
  expect(result).toBe("copied");
  expect(written).toBe("[1] first\n[2] second\n");
});

it("does not write an empty log", async () => {
  let writes = 0;
  expect(await copyDisplayedLog("", async () => { writes += 1; })).toBe("empty");
  expect(writes).toBe(0);
});

it("reports clipboard failure without changing the text", async () => {
  const text = "diagnostic";
  expect(await copyDisplayedLog(text, async () => {
    throw new Error("clipboard denied");
  })).toBe("failed");
  expect(text).toBe("diagnostic");
});
```

- [ ] **Step 2: Run RED**

Run `npm test -- src/lib/log-copy.test.ts`.

Expected: FAIL because `src/lib/log-copy.ts` does not exist.

- [ ] **Step 3: Implement the pure helper and native clipboard bridge**

The helper returns `empty` without calling the writer, otherwise awaits the
writer and returns `copied` or `failed`.

Kotlin parses a `ClipboardWriteArgs.text`, writes
`ClipData.newPlainText("Varmlen VPN log", text)` through
`ClipboardManager.setPrimaryClip`, resolves on success, and rejects with the
exception message on failure. Rust serializes `{ text }` to the mobile plugin.
The desktop branch returns an instruction to use `navigator.clipboard`.

- [ ] **Step 4: Wire the modal**

Add **Copy** between Clear and Refresh. It is disabled when `logText.length ===
0`; Android uses `writeClipboard(logText)`, desktop uses
`navigator.clipboard.writeText(logText)`. Display Copied or Copy failed for
1.5 seconds, then return to Copy. Add English and Russian translation keys.
